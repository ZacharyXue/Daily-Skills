# LC4 寻找两个正序数组的中位数 —— 三层 bug 分类

来源：2026-10 给子皓诊断其三个错误版本（用户自述「之前几次我的解法」）。对拍数据为实测，非估算。

## 一、正确性铁律（讲解时先立这个）

> 每轮淘汰掉的那些元素，必须**能被证明不可能是第 k 小**；而且**淘汰了几个，k 就必须正好减几个**。

三条推论：① 淘汰谁 → 判据是什么；② 淘汰多少 → 有没有被数组边界卡住；③ k 减多少 → 是否恰好等于真实淘汰数。

## 二、正确写法（官方「找第 k 小」）

```python
def getKthElement(k):
    i = j = 0
    while True:
        if i == m:
            return nums2[j + k - 1]
        if j == n:
            return nums1[i + k - 1]
        if k == 1:
            return min(nums1[i], nums2[j])
        ni = min(i + k // 2 - 1, m - 1)      # 关键：先夹边界
        nj = min(j + k // 2 - 1, n - 1)
        if nums1[ni] <= nums2[nj]:           # 关键：比各区间第 k//2 个，不是比队首
            k -= ni - i + 1                  # 关键：k 减真实淘汰数
            i = ni + 1
        else:
            k -= nj - j + 1
            j = nj + 1
```

**为什么比 pivot 能证明？** 设 `nums1[ni] <= nums2[nj]`，则 nums2 的 pivot 之前已排了：nums1 的 `k//2` 个（全 ≤ pivot1）+ nums2 的 `k//2 - 1` 个（全 < pivot2），合计 `k-1` 个不超过 pivot2 → nums1 这 `k//2` 个最多排到第 `k-1` 位，**绝不可能是第 k 小**，可放心淘汰。

## 三、三层 bug（按严重度）

### ① k 的更新对象写错 + 顺序颠倒（最新版致命）
```python
k -= indx1          # ❌ indx1 是「本数组内已排除个数」，k 是「全局第几小」，两个量纲
indx1 += k // 2     # ❌ 用已被改小的 k 再算步长
```
正确顺序：先算 `half = k // 2`，再 `indx += half`、`k -= half`。
- 最小反例 `[1,2,3] vs [4,5,6]` 求第 3 小 → **死循环**（trace：k=2,indx1=2 → `k-=2` → k=0 → `0//2=0` 指针原地踏步；再往下 k=-2 → `-2//2=-1` 指针**倒退**，来回震荡）。
- 最小反例 `[1] vs [2]` 求第 2 小 → 越界 IndexError（`indx1=0` 时 `k -= 0` 没生效，k 仍是 2）。
- 实测失败率 **2978/3961**。

### ② 指针越过数组末尾，k 照减不误（前两版通病）
`indx1 += k // 2` 不检查越界：m=1 时把指针推到 2，**实际只淘汰 1 个，k 却减了 2**。
- 最小反例 `[1] vs [2,3,4,5,6,7]` 求第 4 小 → 期望 **4**，实际 **3**。
- 修法：`ni = min(indx1 + k//2 - 1, m-1)`，k 减 `ni - indx1 + 1`（真实淘汰数）。
- 实测失败率 **650/3961**。

### ③ 判据错：比「队首元素」推不出「这半边能淘汰」（根子上的问题）
三版**都**有这个错，说明不是手滑是理解坑。把 ② 修好、k 更新也写对，只保留「比队首」，5943 组随机用例仍 **失败 1065/5943**。
- 最小反例 `[1,100,101] vs [2,3,4]` 求第 4 小（答案 4）：队首 `1 < 2` 判 nums1 小 → 淘汰 `[1,100]` 两个，**100 被误杀** → 最终给出 3。
- 队首小 ≠ 该数组前 k//2 个都小；数组内部有序不代表整体跨数组有序。

### ④ 索引笔误（更早版的独立 bug）
```python
if indx2 >= n:
    return nums1[indx2 + (k - 1)]   # ❌ 应为 indx1
```
`indx2 == n` 时拿去索引 nums1 必然取错/越界。反例 `[0,0] vs [0,0]` 求第 3 小 → IndexError。实测失败率 840/3961（与 ②③ 叠加）。

## 四、小瑕疵（一句带过，别展开）

奇数分支 `return getKthElement(...)` 返回 int、偶数分支返回 float —— LeetCode 按值比较能过，但类型不一致，建议统一 `float(...)`。

## 五、三量自洽模型（用户重写正确版之后，真正要讲透的那一层）

用户重写的正确版（实测 **0/4969 失败**；20 万元素 ×2 耗时 **134.6 µs**）：

```python
curr1 = min(m - 1, indx1 + k // 2 - 1)      # 看哪
curr2 = min(n - 1, indx2 + k // 2 - 1)
if nums1[curr1] < nums2[curr2]:
    k -= curr1 - indx1 + 1                  # 扔几个 → k 就减几个
    indx1 = curr1 + 1                       # 定新起点
else:
    k -= curr2 - indx2 + 1
    indx2 = curr2 + 1
```

| 量 | 含义 | 公式 | 那个 1 从哪来 |
|---|---|---|---|
| 量1 看哪 | pivot 下标 | `min(len-1, indx + k//2 - 1)` | 「第 t 个」的下标 = `indx + t - 1` |
| 量2 扔几个 | 闭区间长度 | `curr - indx + 1` | 左闭右闭，**两端都算** |
| 量3 减多少 | k 新值 | `k -= 量2` | 铁律：扔几个减几个 |

**统一公式（省得背两套）**：区间内第 t 个元素的下标 = `indx + t - 1`。取 t=k → `indx + k - 1`（提前返回分支）；取 t=k//2 → `indx + k//2 - 1`（pivot）。是同一个公式的两个实例。

### 「减一」的真正价值 = 淘汰数必须 ≤ k-1

写成 `curr = indx + k//2`（不减一）时，pivot 变成区间内第 `k//2 + 1` 个，淘汰数 `k//2 + 1`——形式上量2/量3 仍自洽，**但踩红线**：k=2 时淘汰 2 个 > k-1=1，把答案本身扔掉 → k 归零 → `curr = min(m-1, indx - 1)` 变成负偏移 → 指针乱走。
实测 V5（只去掉减一）：**失败 2825/4969，其中 1344 次死循环、30 次 IndexError**。最小反例 `[1,2] vs [3]` → 期望 2.0 实际 3.0。

### 「少减」才是对的：k 跟物理事实对账，不跟计划对账

`min` 夹住时（nums1 只剩 1 个），实际淘汰 1 个而 `k//2 = 2` → **k 必须只减 1**。硬减 2 等于谎报战果，剩余定位整体漂移一位。

```
[1] vs [2,3,4,5,6,7] k=4： curr1 = min(0, 0+2-1) = 0 → 淘汰数 1（比 k//2 少 1）
  k -= 1 → k=3 → 取 nums2[0+3-1] = 4   ✅
  k -= 2 → k=2 → 取 nums2[0+2-1] = 3   ❌（正是 V2/V6 失败列表第一条）
```

实测 V6（curr 正确但 `k -= k//2`）：**失败 152/4969**。

**因此 `min(...)` 夹取 和 `curr - indx + 1` 记账是配套的一对**：夹取＝「我只对看得见的位置负责」，记账＝「按实际扔掉的个数扣 k」。

### 两个 +1：前提相同、用途不同（用户自己问出来的）

用户原话「indx 的加一是因为上一个 curr 已经被包含了」——**这个判断是对的**，前提假设确实是同一个（curr 属于被淘汰集合）。

| | 式子 | 用途 | 回答的问题 |
|---|---|---|---|
| 计数 +1 | `curr - indx + 1` | 数个数 | 这轮扔了**几个** |
| 定位 +1 | `curr + 1` | 定起点 | 下轮从**哪**看起 |

各去掉一个的实测后果：漏「计数+1」→ 少记一个 → 结果**偏大**（`[1] vs [2..7]`：5.0 vs 4.0；`[1,3] vs [2]`：IndexError）；漏「定位+1」→ 反复淘汰同一元素 → 结果**偏小/越界**（`[1] vs [2..7]`：1.0 vs 4.0）。

**要点：同一个事实被拿来干两件不同的事，两处都得写——「前提相同」≠「可以合并」。**

## 七、复用注意

- 这是「三版都错」的典型案例：**用户连续几版踩同一个坑 → 是理解问题，改参数没用，必须讲原理**。
- 讲解收尾的开放式问题（已验证好用，按此顺序递进）：
  1. 让用户拿 `[1,100,101] vs [2,3,4] k=4` 自己走一遍正确写法，并**口头证明「为什么被淘汰的这 2 个不可能是第 4 小」**（考察判据的证明力）。
  2. 「被 `min` 夹住时，淘汰数比 `k//2` 大还是小？为什么『少减』反而必须？」——用户第一次答成「没有少减」并把问题理解成「+1 怎么数」，**用 trace 数字纠正**（减 1 vs k//2=2），这是全题最微妙的一步。
  3. 「`k -= curr-indx+1` 的 `+1` 和 `indx = curr+1` 的 `+1`，各自的前提假设是什么？」——用户能答出「curr 已被包含」，此时点明「前提相同≠用途相同」。
  4. 收网问：「被夹住时把 nums1 剩余全部扔掉，为什么一定安全？」（逼他绕回 pivot 比较的证明）。
