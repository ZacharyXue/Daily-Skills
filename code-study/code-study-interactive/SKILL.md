# 交互式源码深读

与 cron 每日阅读互补的**问答驱动**深读模式。参见 `references/mode-comparison.md`。

## 触发条件

用户对某个已 cron 推送过的模块发起追问：
- "xxx 是怎么回事？"
- "帮我详细讲讲 xxx 这个函数"
- "根据代码，详细讲讲 xxx 是怎么一个判断逻辑呢？"

## 交互原则

1. **先讲清概念**：用自己的话解释设计意图，用大白话，先不贴代码
2. **代码佐证**：每个论断带文件路径 + 行号，贴关键片段（10-30 行）
3. **用图验证**：复杂流程画 Excalidraw，数值实例走 3 个场景
4. **追踪追问链**：用户确认理解 → 追问下一层 → 继续深挖 → 直到用户说"帮我总结"
5. **工具受阻时回退**：飞书文档创建失败 → 直接在对话中图解 + 解释，不反复重试

## 产出三合一

1. **Excalidraw 图** (.excalidraw 文件)：拖到 excalidraw.com 可编辑
2. **对话解释**：即时可读，含代码行号引用
3. **飞书文档**（可选项）：永久可检索

## 代码引用规范

- 每个论断必须带 file.go:line
- 用 `←` 注释标注关键行
- 解释代码时回答"为什么这样写"

## 图解规范

- 3+ 步骤的流程必须画图
- Excalidraw 手绘风格，图自包含（标题 + 流向 + 注释）
- 配合数值实例（至少 3 个场景：正常/边界/失败）
