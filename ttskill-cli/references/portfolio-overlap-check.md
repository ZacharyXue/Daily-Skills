# 组合重叠体检（两层法）—— portfolio-overlap-check

**何时用**：用户说「我的基金是不是买重了」「帮我看看组合有没有重复」「这几只基金是不是一回事」「组合体检/分散度」；
主动基金评估里「同经理多产品复制」是它的单点特例（见 `active-fund-evaluation` Step 7）。

**一句话原理**：名义基金数 ≠ 独立 beta 数。用**净值层相关性**做主判、**持仓层重叠度**做辅判，两层交叉才能看出"买了好几只其实是一回事"。

```bash
export PATH="$HOME/.local/bin:$PATH"
python3 scripts/portfolio_overlap.py --from-holdings              # 从账户持仓取全部基金
python3 scripts/portfolio_overlap.py --codes 515180,159545,012708 # 指定基金（候选池/外部基金）
# 产出 /tmp/portfolio_overlap/report.md + raw.json（默认目录）
```

---

## 一、两层法：为什么净值层是主判（2026-10-18 实测教训）

| 层 | 指标 | 数据 | 适用 | 盲区 |
|---|---|---|---|---|
| 净值层（主判） | 周收益 Pearson（近 24 个月，≥52 共同周） | `nav_history.items` 的 `JZZZL` 日收益 → 按 ISO 周复利聚合 | **所有基金**，尤其指数/宽基/QDII | 只反映历史同涨同跌，不反映当下持仓差异 |
| 持仓层（辅判） | 两两 Σmin(w)（重叠度） | `heavyweight_position_latest.fundStocks` 前十大 | **主动基金的选股重合** | 前十大只覆盖基金 3%-60%；不同指数权重不同但 beta 相同 → 系统性低估指数基金之间的重复 |

**实测证据（同一组合，两层结论相反）**：
- 持仓层：只有 1 对 >20%（摩根标普500 × 摩根纳指100 = **29.7%**），其余全 <11% → 看上去"很分散"
- 净值层：253 对里 **44 对 r≥0.8**，其中天弘标普500FOF × 摩根标普500 = **r 0.996（几乎是同一个东西）**；三只中证500增强两两 r=0.97×3

→ **规则 1：两层结论冲突时以净值层为准。** 用持仓 Σmin 判断指数基金分散度是无效的。

**分级阈值**（沿用长江 CJPY `cj-portfolio-overlap` 口径，实测可用）：
- 持仓重叠度：<20% 低度 / 20-40% 中度 / 40-60% 显著 / ≥60% 高度
- 相关性：≥0.97 几乎同一个 beta / ≥0.9 高度重复 / ≥0.8 显著相关 / ≥0.6 相关
- 聚类：并查集在阈值上合并 → 输出「名义 N 只 → 实际 M 个独立 beta」；**M 才是真实分散度**

## 二、固定规则（每次跑本流程都遵守）

1. **净值层为主判，持仓层为辅判**；冲突以净值层为准（理由见上）。
2. **数据缺口显性化，绝不当 0 重叠**：FOF / ETF 联接 / 债券 / 货币没有股票前十大，必须单列"未穿透"清单，且不计入重叠率分母。联接基金要穿透到目标 ETF，FOF 要穿透到 `fundfofs`（当前 BASE_INFOS 的 `fundfofs` 常为空 → 标缺口，别硬算）。
3. **净值相关性用日涨跌幅复合到周**（`JZZZL`），不用单位净值 `DWJZ`——分红日会被当成暴跌。
4. **组合层穿透**：重复个股按 `Σ(持有市值 × 基金内权重)` 汇总 → 输出"实际暴露"，比看单只基金的权重有信息量。
5. **结论只给位置，不给综合结论**：报"哪些基金挤在同一个 beta 上、各占组合多少"，不报"你该卖掉谁"。
6. **失败要重试**：ttskill 偶发返回 0 字节，重试一次即恢复（脚本内置），别判死源。

## 三、字段与信封（实测，写死）

- 持仓清单：`ACCOUNT_HOLDING --action holding_list --body '{}'` → `body.holding_list_result[]`；
  字段 **`ptype`（小写！）**：`fund` / `tg`（投顾）/ `hqb`（活期宝）；过滤后才是纯基金清单
- 全档案：`TTFUND_BASE_INFOS --body '{"fcode":"<code>","nav_range":"ln"}'`
  → 真实数据在 `d['data']['raw_result']['body']['expansion']['comprehensive_info']`
- 前十大：`fund_profile_holdings.heavyweight_position_latest.fundStocks[]`，
  字段 **`GPDM`(代码) / `GPJC`(名称) / `JZBL`(占净值比)**；披露日在 `heavyweight_position_report_date`
- 净值：`nav_history.items[]`，字段 `FSRQ`(日期) / `JZZZL`(日涨跌%) / `DWJZ`(单位净值)
- 资产配置：`fund_profile_holdings.asset_allocation_latest`（`GP`股票/`ZQ`债券/`HB`现金）
- 脚本已带缓存（默认 `/tmp/fund_raw/<code>.json`），重复运行不会重复拉取

## 四、实测样板：子皓持仓（2026-10-18，25 只基金 / ¥112,503）

**净值层**：
- r=0.996 ★ 007721 天弘标普500FOF × 017641 摩根标普500（同一 beta，且是真正的重复持有）
- r=0.989 / 0.986 / 0.98：014201 天弘中证1000增强 × 015867 国泰海通中证1000增强 × 018653 万家国证2000增强
- r=0.975×3：006593 博道 / 007994 华夏 / 014344 鹏华（三只中证500增强，两两）

**聚类**：
- r≥0.9：25 只 → **16 个簇**（多基金簇 2 个）
- r≥0.8：**11 个簇**，A 股权益挤成 1 个 10 只的簇（11.5%），海外挤成 1 个 6 只的簇（8.7%）
- r≥0.6：红利线（013776 中泰兴为 / 012708 东方红红利低波 / 022719 港股通央企红利）合成第 3 个簇 —— 这是组合里**真正的另一条腿**

**持仓层**：仅 017641 × 019172 = 29.7%（苹果/亚马逊/谷歌）达中度，其余全低度

**穿透重复个股**：美光科技（4 只基金持有）、英特尔 / 拉姆研究 / 谷歌-C / 广钢气体 / 长川科技 / 亚马逊 / 君正股份（各 3 只）

**顺带发现**：013776 中泰兴为价值精选股票仓 91.25%、**前十大占净值 82.7%**（单票顶格）→ 组合里最集中的主动基金；债券+货币占 59.2%。

## 五、输出怎么读

1. 先看「独立 beta 数」——这个数字和名义基金数的差距就是虚分散的量。
2. 再看多基金簇里**每只在组合中的占比**：如果同一个 beta 上的多只合计占比很小（如 3.8%），问题不是重复，是"仓位过于零碎、每只都不足以影响组合"；如果合计占比大（如 11.5%），才是真的集中度风险。
3. 最后看数据缺口清单——**未穿透的部分不要下"分散"结论**（本次 FOF+联接共 3 只未穿透）。
4. 与 `active-fund-evaluation` 的六维表配合：本流程给"组合层"视角，六维表给"单只值不值得买"视角。
